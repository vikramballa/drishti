# Architecture decision log

One entry per decision: date · decision · reason · alternatives considered.
Spec deviations are marked **[spec]**.

## 2026-11-11

1. **Single self-contained binary.** `drishti` contains the CLI, API server, core engine, worker entry point and the embedded web UI (rust-embed). *Reason:* the owner asked for minimal memory/disk use on a MacBook; one ~11 MB binary, no runtime dependencies, no Docker or JVM required. *Alternatives:* separate `drishti-worker` binary/crate (spec §5) — folded in as `drishti worker` with the identical CLI contract (§7.7). **[spec]**

2. **Core engine runs in-process; Docker is optional and only for heavy engines.** The core engine only parses and decodes (never executes input), so it does not need a container. Ghidra/angr/JADX workers (phases 3–4) will run in sandboxed containers as specified. *Reason:* Docker Desktop on macOS costs 2+ GB RAM and was not running on the dev machine. Spec §3.2 allows "core may run in-process".

3. **On-demand CFGs instead of storing blocks.** Analysis keeps one compact summary per function (extent ranges, counts, call targets). Blocks/edges are rebuilt by re-exploring the function when it is viewed (`Analysis::cfg`), which is deterministic and takes microseconds. *Reason:* measured peak heap on Electron Framework (206 MB) dropped from ~3.1 GB to ~360 MB. *Alternative:* compact block arrays (~2.5× smaller only).

4. **Inputs are memory-mapped (`memmap2`).** Files cost page cache (reclaimable), not heap. Uploads stream to disk while hashing (constant memory). Local mode can **analyse files in place** (`POST /binaries/open`) without copying them into the blob store.

5. **AArch64 control flow via direct encoding match; capstone only for display.** Branch/ADRP/ADD/LDR/CMP semantics are decoded with bit masks (ARM ARM C4.1), which is allocation-free and far faster than capstone with detail. Capstone renders text only for visible windows. x86 uses iced-x86 for both.

6. **Function-start partitions.** `LC_FUNCTION_STARTS` (Mach-O), `.pdata` (PE) and `.eh_frame` FDEs (ELF) define authoritative extents: jumps leaving an extent are tail calls and no new function may start strictly inside one. Removed ~9,400 false functions on Telegram. **Compact unwind (`__unwind_info`) is used for seeds only**, because ld merges adjacent functions with identical encodings into one entry, so it is not a partition.

7. **rusqlite (bundled SQLite) instead of sqlx.** *Reason:* local, low-concurrency tool; synchronous API, no macro/compile-time DB, smaller build. Postgres support (spec §7.13) is deferred. **[spec]**

8. **Raw-body uploads instead of multipart.** `POST /binaries?name=…` with the file as the body. *Reason:* streaming without an extra multipart parser; trivially used from curl/the UI. **[spec]**

9. **Hand-maintained OpenAPI route index** at `/api/v1/openapi.json` instead of `utoipa`. *Reason:* avoids a heavy macro dependency in phase 2; revisit when the API stabilises. **[spec]**

10. **Web UI: Preact + TypeScript + Vite, no Monaco/Cytoscape/Tailwind/TanStack.** Own virtualized list, own layered graph layout (Sugiyama-lite) and pan/zoom/pinch. *Reason:* whole UI is ~22 KB gzip JS + 4 KB CSS (vs several MB), loads instantly on phones, embeds in the binary. React API compatibility keeps a later move possible. **[spec]**

11. **No TLSH/ssdeep yet.** SHA-256 + MD5 only. TLSH adds a C dependency; deferred to phase 4 with YARA. **[spec]**

12. **Analysis results are not persisted for the core engine.** Re-analysis is fast (Telegram 190 MB: ~2 s) and avoids writing multi-hundred-MB JSON. `drishti analyze`/`drishti worker` still write `normalized.json`. Engine caching by `(sha, engine, version, options)` will apply to heavy engines (phase 3). **[spec]**

13. **Server mode requires `DRISHTI_TOKEN`.** Binding to a non-loopback address refuses to start without a token; requests need `Authorization: Bearer`. In-place path opening is disabled in server mode (it would expose server files).

14. **`make` instead of `just`** (spec §4.2 allows either; `just` was not installed).

15. **Dependencies added** (justification): `memmap2` (zero-copy input), `rust-embed` + `mime_guess` (embedded UI), `futures-util` (streaming upload body), `zip` with `deflate-flate2-zlib-rs` only (container listing without compression extras), `cpp_demangle`/`msvc-demangler`/`rustc-demangle` (spec §7.2 demangling).

16. **Container listing reads only a 64-byte prefix per ZIP entry** for classification — zip bombs cannot exhaust memory. Full extraction (with ratio/size/traversal guards, spec §8.4) arrives with phase 4 children analysis.

17. **MCP server implemented in Rust, in-process (`drishti mcp`), not in Python over the HTTP API.** *Reason:* zero extra runtime, works without a running server, and reuses the engine directly. Renames/comments are written to the same SQLite database so the UI sees them. Tools address binaries by path rather than `binary_id`. **[spec]**

18. **Behaviour detection, IOC extraction, hardening checks and crypto-constant scanning are built in** as small rule tables rather than bundling capa/YARA/checksec. *Reason:* keeps the single small binary; rules are plain data in `drishti-disasm/src/insights.rs` and `drishti-loader/src/insights.rs`. YARA remains planned as an optional engine (phase 4).

19. **Binary diff uses address-masked instruction fingerprints** (AArch64: PC-relative immediates masked; x86: opcode + register operands). Matching is name → unique fingerprint → positional pairing between anchors. Simple and fast (seconds on 250k functions); no graph-based matching yet.

20. **Opening a binary starts analysis automatically** and resumes file watching for in-place binaries, so results survive server restarts without persisting analysis output.

21. **Diff v2: similarity matching for unnamed functions** (imports, strings, data refs, immediates, op-class histogram, call-graph neighbours; mutual best match above a threshold), after name and exact-fingerprint anchors. *Reason:* positional pairing matched 0 % of O0↔O2 corpus functions; v2 matches 94 %. New CLI `drishti diff OLD NEW`. *Alternative:* BinDiff/Diaphora-style full graph isomorphism — heavier, not needed yet.

22. **Persisted analysis cache** (`drishti-disasm/src/cache.rs`, own varint format, `ANALYSIS_REV`) in `data/cache/`, keyed by sha + engine version + options, shared by the server and `drishti mcp`. Supersedes the "don't persist analysis output" part of #20. *Reason:* Telegram reopens after a restart in ~260 ms instead of re-analysing (2+ s). No `bincode` dependency: the format is ~500 lines and versioned by hand.

23. **PE test samples are cross-built with clang + `rust-lld`** (`corpus/build-pe.sh`, `.def` import libraries) instead of `zig cc` or MinGW. *Reason:* both are already present with the Rust toolchain; no new install. CI sets `DRISHTI_REQUIRE_PE=1` so missing samples fail instead of skipping.

24. **Own iterative Mach-O export-trie walker** replaces `goblin::mach::MachO::exports()`. *Reason:* fuzzing found a goblin panic (`libs[ordinal]` out of bounds on a bad re-export) and a stack overflow from its recursive walk on hostile tries. Ours visits each node once (cycles end), caps names at 4 KB, and returns only address-bearing exports; a test checks it matches goblin on system binaries, and it matched exactly on Telegram, Electron and Chrome Framework (11 004 exports).

25. **`@playwright/test` 1.64.1 (web devDependency only)** for `make e2e`. Pinned to the release whose Chromium build (1248) was already cached on the dev machine. Not part of the shipped binary.

26. **Analysis memory: avoid freed-but-cached heap.** macOS malloc keeps recently freed large blocks, so growth by `realloc` and per-round temporaries inflated the footprint well above the live heap (Chrome Framework: 754 MB footprint, 415 MB live). The analyser now reserves the xref table once from the code size (untouched capacity costs only address space), reuses `explore()` scratch tables and gap-scan buffers, drops exploration state before building final tables, and builds `called_by` and the by-`from` index without large temporaries. Output is byte-identical. `DRISHTI_MEMSTAT=1` now also prints the process footprint per phase. *Alternative tried:* `malloc_zone_pressure_relief` at phase boundaries had no effect; a different global allocator (mimalloc) would add a C dependency.

27. **Server: single-flight session loads, and no re-hash on reopening an unchanged in-place file.** Concurrent requests for a binary that isn't in memory now wait for one load (per-sha async lock) instead of each loading a full image + analysis; the UI fires several requests on open, so Telegram peaked at 366 MB instead of 199 MB after a restart. Reopening an in-place file whose path, mtime and size match the database reuses the stored sha and FileInfo (Telegram: ~1 s → 1 ms). *Trade-off:* a file rewritten with identical size and a restored mtime is not noticed — the same signal the file watcher already uses.

28. **Code ranges are clipped to bytes that exist in the file** (`Image::finish`, all formats). Section headers are file data; a fuzzed Mach-O claiming a 9.2×10¹⁸-byte code section made gap scanning walk it byte by byte (a hang). A zero-fill tail (PE `VirtualSize > SizeOfRawData`) is clipped silently; a header that points past the end of the file adds a warning. Output on the corpus, PE samples, system binaries, Telegram, Electron and Chrome is unchanged. Section end addresses use saturating arithmetic.

29. **PDF provenance + safety triage in-house** (`drishti-loader/src/pdf.rs`), not `lopdf`/`pdfid`. A tolerant scanner finds `N G obj` headers (it doesn't trust the xref table), decompresses only object streams and the XMP packet (FlateDecode, capped at 16 MB each and 96 MB in total), and caps depth, counts and string sizes. It reports metadata (Info, XMP, older revisions' Info), revisions, IDs, signatures (the leaf certificate's subject = signer, its issuer), fonts, links, attachments, and pdfid-style features with `#xx`-escaped names decoded. A rule table (~120 producers) turns these into plain-language "where it came from" clues with a confidence level. Pulled forward from phase 4 at the user's request. *New dependency:* `flate2` directly in the loader (already in the tree via `zip`, same `zlib-rs` backend). Fuzz target `pdf`. **[scope]**
30. **macOS download origin via `/usr/bin/xattr`** (`drishti-server/src/origin.rs`) for `kMDItemWhereFroms` (own minimal bplist reader) and `com.apple.quarantine`. *Reason:* the server crate forbids `unsafe`, so no `getxattr` FFI, and no new crate. It runs a system tool on the input path; it never executes the input. Only for files opened in place, because browser uploads drop xattrs.
31. **Local AI assistant in the Rust server** (`drishti-server/src/ai.rs`), not `python/drishti_ai` (spec §7.10). It talks to Ollama (`/api/chat`, NDJSON) or any OpenAI-compatible local server (`/v1/chat/completions`, SSE) over plain HTTP using `hyper` client features (`client`, `http1`) + `hyper-util` (`tokio`) + `http-body-util`, all already in the tree via axum. Answers stream to the browser as text. The model sees only a capped FACTS block built from Drishti's own results, marked as untrusted data. Ollama `:cloud` models are never auto-selected (§8.7, local by default), and in server mode the AI URL comes only from `DRISHTI_AI_URL` (no SSRF through settings). Claims/verifier (roadmap D3) is not done yet. **[spec]**


32. **Outbound HTTPS through the system `curl`** (`drishti-server/src/net.rs`) for the opt-in cloud features (cloud AI, online lookups, rule downloads), not a TLS crate (`rustls`/`reqwest`). *Reason:* keeps the single binary small with no new crypto dependency. URL, headers (API keys) and body go to curl as a config file on **stdin**, never argv, so keys don't appear in `ps`. Only `https://`, no redirects for API calls (rule downloads allow up to 5 https→https redirects), bounded time and size. Header values with newlines are rejected. **[spec §8.6]**
33. **External tools run as sandboxed local subprocesses, not Docker workers** (spec §8.2 deviation). macOS `sandbox-exec` profile: everything denied for network, writes only to the tool's work folder + temp, `HOME` redirected into `data/tools/home`; per-run timeout kills the whole process group; stdout/stderr go to files and are read capped; heavy tools (Ghidra, capa, FLOSS, ClamAV, JADX, ILSpy) run one at a time. Without a sandbox (non-macOS) tools refuse to run unless `tools.allow_unsandboxed` is set. *Reason:* Docker isn't running on the 16 GB target machine and a JVM container per request would cost far more memory; the sandbox gives the two properties that matter (no network, no writes outside the work dir) and was verified (curl fails DNS, writes to `$HOME` are denied). **[spec]**
34. **Tool adapters live in Rust (`drishti-server/src/tools/`), not `python/drishti_adapters`, and return a plain-language result** (`verdict`, `headline`, `items`, `data`) instead of `normalized.json`. *Reason:* these tools add findings, metadata and source trees, not functions/CFGs, and the UI's first reader is a non-expert. Results are cached per (sha, tool, tool version, rules version) under `data/tools/results`, with `data/tools/` pruned to 4 GB. Registry: Ghidra, radare2, capa, FLOSS, YARA, ClamAV, ExifTool, oletools, binwalk (scan only, no extraction), JADX, ILSpy, WABT (`wasm2wat`; wabt 1.0.42 dropped `wasm-decompile`), ipsw class-dump/swift-dump. **[spec]**
35. **Ghidra per function, on demand** (`tools/decompile.rs`, `scripts/DrishtiDecompile.java`): headless import into a per-file project (full auto-analysis only for files ≤ 12 MB; larger files import with `-noanalysis` and the script disassembles + creates just the requested function), then `-process … -readOnly` per request. Addresses are mapped by the image-base difference. Universal Mach-O: the analysed slice is written out so Ghidra imports the right one. Telegram: 9 s for the first function, ~3 s after; `GHIDRA_MAXMEM=2G`. radare2 (`pdg` with r2ghidra, else `pdc`) is the light alternative. Java script, so no PyGhidra/Jython.
36. **New direct dependencies:** `zip` in `drishti-server` (same version/features as the loader's; safe extraction of rule archives with traversal and size limits) and tokio's `process` feature. No other crates.
37. **API keys** (`secrets.rs`): `data/secrets.json` written atomically with mode 0600, environment variables (`ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `GEMINI_API_KEY`, `OPENROUTER_API_KEY`, `GROQ_API_KEY`, `VT_API_KEY`, `ABUSECH_AUTH_KEY`, `ABUSEIPDB_API_KEY`) win. The API only reports set/source/last-4; keys are validated (8–512 printable chars, no quotes/backslashes/whitespace). Covered by `drishti-cli/tests/safety.rs`. **[spec §8.6]**
38. **Cloud AI providers** (Anthropic Messages API; OpenAI, Gemini, OpenRouter, Groq via OpenAI-compatible chat) with fixed endpoints, opt-in by three explicit steps (mode = cloud, key, consent checkbox that states exactly what is sent), and a per-file "keep private" switch (`file.local_only.<sha>`) that forces the local model. Suggested Anthropic models: `claude-sonnet-5-5` (default), `claude-opus-5-5`, `claude-haiku-5-5`. FACTS lines are numbered `[F#]` and the model is asked to cite them; `/ai/facts` lets the UI show the fact behind a citation (a first step towards roadmap D3; claims aren't machine-verified yet). Answers can be "very simple", "normal" or "technical". Tool results, online-lookup results and cached decompiled code are added to the facts. **[spec §7.10, §8.7]**
39. **Online lookups** (`lookup.rs`), off by default (`online.enabled`), each run by an explicit click: VirusTotal and MalwareBazaar get only the SHA-256; URLhaus gets domain names found in the file (max 20, local/example names skipped); AbuseIPDB gets public IPv4 addresses (max 10, private ranges skipped). Results cached in `data/lookups/`. **[scope]**
40. **Plain-language report** (`plain.rs`): verdict (good / caution / danger / unknown) with ranked reasons, maker (from `codesign -dvv` for in-place apps, Authenticode for PE, document metadata for PDFs), phone-style permissions merged from entitlements + `NS…UsageDescription` (the developer's own explanation) + code behaviours, web addresses grouped by owner (maker / tracking / ads / platform / mentioned-only), a built-in table of ~50 third-party SDKs (analytics, ads, crash reporting, attribution, updates, payments…) matched on bundled frameworks, URL hosts, archive paths and whole-word class names, and A–F grades. App bundles are read with `/usr/bin/plutil` (JSON, falling back to XML + a small parser for plists with dates/data) and signatures with `/usr/bin/codesign`; both only read. Full signature verification is a separate endpoint (`/trust`) because it hashes every sealed file. **[scope]**
41. **Whole-Mac checks** (`mac.rs`, local mode only): launch agents/daemons with their program, signer and a plain verdict (Homebrew programs and empty leftovers explained), and a quick scan of `/Applications` (+ `~/Applications`, Utilities): signer, notarization, requested permissions, bundled kits. Read-only; Drishti never changes or removes anything. **[scope]**
42. **UI redesign** (web/): Simple mode (default: Summary, Ask, Safety checks, Hidden details, Look inside, Notes) vs Expert mode (adds Code, Flow graph, Calls, Functions, Text inside, Imports/Exports, Raw bytes, Search, Compare). Side navigation instead of 11 tabs; the function list only appears next to code views. One teal accent; red/amber/green only carry safety meaning; system fonts and a hand-drawn inline SVG icon set (no web fonts, no icon library, works offline). Glossary tooltips for technical terms, a 4-step first-run tour, skeleton loaders, light/dark parity. Code view gains "Readable code" (Ghidra/radare2).
43. **Not done in this round:** building the r2ghidra plugin (the install was blocked in the agent session; the UI shows the command), Python bytecode tools (pycdc/pyinstxtractor are not packaged for Homebrew), Unicorn/Qiling emulation (belongs to milestone B), Binary Ninja (commercial), Detect It Easy (overlaps the built-in detector), webcrack (needs npm downloads at run time). ILSpy is wired up but untested here (no .NET SDK installed). *(2026-11-12: now tested; `tools::run` sets `DOTNET_ROOT` for Homebrew's .NET.)*
44. **Advanced search** (`drishti_disasm::search`, shared by API, CLI `drishti search` and MCP): text (case-insensitive, UTF-8/UTF-16LE/BE), YARA-compatible hex (nibbles, jumps, alternatives, `~`), regex over raw bytes, numbers (every int width that fits + f32/f64, either byte order), scope (code/data/section), instruction patterns with `;` sequences, a function query language (`calls:` `callers:` `str:` `refs:` `size>` `is:` `-term`), regex/encoding/length/referenced filters on strings, and search across every file in the library (mmap only, no parsing). Results are capped (100k byte hits, 20k instruction hits) and time-boxed (20 s; 30 s across files). New dependency: `regex` 1.13 (its automata were already in the tree via tracing-subscriber); about +1 MB binary. **[dependency, scope]**
45. **Counting allocator only counts with `DRISHTI_MEMSTAT`**: the shared atomic counters updated on every allocation made multi-threaded work several times slower (cache-line contention). Instruction search runs on up to 8 threads and renders through a bounded `disasm_bounded` with a thread-local Capstone handle: 30.5M AArch64 instructions (WhatsApp, 1M functions) in about 4 s instead of 60 s+.

## 2026-11-12 (agent analysis round: vuln hunter, NL query, triage, IR B1)

46. **Vulnerability auditor is call-graph reachability, not value taint** (`drishti-disasm/src/vuln.rs`). It resolves untrusted-input "sources" (recv/read/fread/getenv/accept/SSL_read/…) and dangerous "sinks" (system/exec*/posix_spawn/strcpy/sprintf/memcpy/scanf/printf-family/dlopen/LoadLibrary) to the functions that reference them (reusing the `insights::behaviors` xref+stub resolution), then multi-source forward BFS over the call graph (depth ≤ 12) connects them. Confidence: **high** = source and sink in the same function, **medium** = a call path exists, **low** = a banned API (strcpy/system/…) with no input path. Fortified `_chk` variants are matched (macOS emits `___strcpy_chk` at -O0) and down-ranked (they abort instead of corrupting). *Reason:* honest, fast (Telegram 255k fns < 1 s, +0 MB footprint), and reuses existing infra; **true value-level taint waits for the IR (milestone B)**, which the UI/report say explicitly. No binary rewriting / patch output — the user chose analysis-only (feature 5). **[scope]**
47. **Natural-language function search translates to the existing query language** (`drishti-disasm/src/nlq.rs`), not a new query backend. A deterministic keyword→term mapper (JSON→`str:json`, "shell command"→`calls:system`, "complex"→`complexity>20`, "unused"→`callers=0`, size hints→`size>N`, …) emits a `search::FnQuery` string, which is parsed and run like a hand-typed one and **shown to the user** (transparent, editable). Terms are ANDed (no "or"). `nlq::SYSTEM_PROMPT` carries the grammar + few-shot for a future AI translator; the heuristic is the offline default so the feature needs no model or key. **[scope]**
48. **Triage briefing composes existing engines** rather than a new analysis: the MCP `triage` tool joins the plain summary, hardening, behaviours, IOCs and the vuln-audit severity counts into one executive text; the server already exposes the same pieces via `/insights`. Realises spec phase-7 "triage specialist" as an agent-orchestrated workflow over MCP. **[spec]**
49. **New MCP tools** (`drishti mcp`, now 16): `triage`, `find_vulns`, `nl_query` — the agent surface for the "autonomous RE team" (feature 1). They reuse the same cached load path as the other tools; `find_vulns`/`nl_query` honour user renames offline. **[spec]**
50. **New API + UI surfaces:** `GET /binaries/{sha}/vulns`, `POST /binaries/{sha}/nl-query`; web "Weak spots" page (plain-language, both Simple/Expert, links to code) and a plain-English box in the Functions view. No schema change (the new types are server/engine serde, not `drishti-model`).
51. **`drishti-ir` crate (milestone B1)**: P-code-like typed IR (varnodes `Reg`/`Temp`/`Const`/`Mem`, the spec §7.4 op set), a pretty-printer and a deterministic reference interpreter (`docs/IR.md`). Zero deps beyond serde. It is the oracle for the B3 Unicorn differential tests and the substrate for B2's lifters; not yet wired into analysis. **[spec]**

## 2026-11-15 (Days 2–4)

52. **IR shrunk before the lifter** (`drishti-ir`): registers are `RegId(u16)` (high byte = architecture, low byte = index into a per-architecture table in `regs.rs`; full registers only, sub-registers are narrower widths), constants are `u64` with a boxed `Wide` variant above 64 bits, `Var::Mem` is gone, and destinations are a separate `Place` type (register or temporary), so "assign to a constant/memory" can't be expressed. `Intrinsic` is boxed. `Var` 32 → 16 B, `Insn` 128 → 56 B, no heap per register mention (a `sizes` test keeps it there). Narrow register writes zero-extend into the full register (AArch64 W/scalar-FP, x86-64 32-bit); x86 8/16-bit writes must be lifted explicitly. Fixed on the way: shift amounts ≥ 2³² were truncated to `u32` (a shift by 2³²+1 acted as a shift by 1), and `Concat`/`Extract` could overflow at 128 bits.
53. **Compact xref table** (`drishti-disasm/src/xrefs.rs`): xrefs are 12-byte `(to, from)` `u32` offsets from the image's lowest mapped address + a 1-byte kind, filled during analysis. Anything that doesn't fit (images spanning > 4 GiB, targets outside the image) goes to a side table of full 24-byte `XrefC`s and iteration merges the two, so there is no all-or-nothing fallback. Order is now total `(to, from, kind)`, which also makes `dedup` remove every duplicate (before, an unstable sort on `(to, from)` could leave one). `xrefs_to` returns a borrowed `Xrefs` view instead of `&[XrefC]`. Cache format 2 stores the offset base so decoding fills the compact table directly; `ANALYSIS_REV` 3. Output byte-identical on the corpus, Telegram and Chrome.
54. **AI answers end with a `<claims>` block** (`drishti-server/src/claims.rs`): one `kind: value` line per concrete thing the answer relies on, for kinds `calls` (`caller -> callee`), `imports`, `string`, `address`, `function`. A line-based format rather than JSON because small local models follow it more reliably, and a cut-off stream still yields the complete lines. The parser is lenient (bullets, fences, quotes, `[F#]` citations, missing closing tag) and drops unknown kinds. `POST /binaries/{sha}/ai/claims` returns `{prose, claims, checked: false}`; the UI hides the block while streaming and lists the claims under the answer as "not checked yet". Answers without a block display unchanged. The checker (Day 5) will fill in `checked`.
## 2026-11-15 (Days 5–12)

55. **AI claim checker** (`claims::check`, Day 5): each parsed claim is tested against the open file through a small `Evidence` trait (functions by name/address, mapped addresses, imports and linked libraries, the call graph, text in the file), so the checker is unit-tested with a fake. Verdicts: **verified** (the file shows it), **refuted** (the file is analysed and shows the opposite, e.g. no such import, `a -> b` where `a` never calls `b`), **unverified** (can't tell: unknown name, not analysed, prose instead of a value). Refuted means Drishti looked in an analysed file and didn't find it; for calls the reason says that calls through pointers can't be ruled out. `/ai/claims` now returns `checked: true` with a status + plain reason per claim; if the file isn't open every claim is unverified. UI: badges per claim, a warning line when anything is wrong (and the list opens), and "Unverified: this answer made no claims Drishti can check" for answers without a block.
56. **AArch64 lifter decodes encodings directly** (`drishti-ir/src/a64.rs`, Days 6–8), not from Capstone's operand structs: the encoding is the ground truth Unicorn tests against, Capstone details are slower and lossy (aliases), and it keeps `drishti-ir` dependency-free. Integer, load/store (all addressing forms, pairs, exclusives, LSE atomics, LD1/ST1), branches, system hints and SIMD&FP *moves* have full semantics; FP/SIMD arithmetic and crypto lift to `INTRINSIC a64.<class>(word)`. Single-threaded model: exclusive stores succeed, barriers are no-ops, PAC branches act like their plain forms. AArch64 register ids are fixed (append-only; `tpidrro_el0` added as id 72). **[spec §7.4]**
57. **Lifting is on demand, cached by bytes** (`drishti-disasm/src/lift.rs`, Days 9–10): a function is lifted from the analysis's code ranges only when asked (`GET /binaries/{sha}/functions/{addr}/ir`, `drishti lift F ADDR`), into a byte-capped LRU (`LiftCache`, `DRISHTI_LIFT_CACHE_MB`, default 64 MB, counts the `Insn` vector + boxed intrinsics). `drishti lift F --coverage` reports the share of instructions with full semantics by class; `--cache-mb N` is the load test. Nothing is lifted during analysis, so memory without lifting is unchanged.
58. **Differential tests against Unicorn live in a test-only crate** (`crates/drishti-difftest`, Days 11–12; new dependencies `unicorn-engine` 2.1.5 and `proptest` 1). Unicorn is GPL-2.0, so the crate is `publish = false`, outside the workspace's `default-members`, and no shipped crate depends on it (`cargo tree -p drishti-cli` has no unicorn/proptest). `make difftest` (part of `make check`; skipped with a note if `cmake` is missing) runs one instruction in both from the same random machine state and compares X/SP/NZCV/V registers, memory and the next PC, over 37 encoding groups. Known-different cases are excluded with reasons (`excluded()`: PAC, exclusive monitors, Armv8.5+/8.7 instructions newer than Unicorn's CPU, a Unicorn 2.1.5 signed-atomics bug where the lifter matches real Apple silicon). **[dependency]**
59. **Rust pinned with `rust-toolchain.toml` (1.100.0)** for local `make check` and CI.
